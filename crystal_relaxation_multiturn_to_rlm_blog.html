Crystal Relaxation Architecture Shift

From MultiTurnEnv to RLM

The move from a classic multi-turn environment to an RLM harness was not a cosmetic refactor. It changed where the task lives, how the agent acts, what the evaluator can trust, and which failures are real science problems instead of format noise or environment plumbing.

Legacy loop: direct feedback in chat New loop: taskset + harness + ComposableEnv Outcome: harder benchmark, cleaner signal

In the crystal relaxation project, the old setup was good at testing whether a model could emit a plausible final CIF under a tight feedback loop. The RLM version asks a more serious question: can the model actually operate as an agent, use tools, inspect intermediate state, and converge on a physically better structure under a realistic workflow?

Examples of smart Python use in RLM evals

The RLM traces are useful because they show models using Python as an analysis tool, not just as a way to emit text. In the GPT-5.5 run, some of the best rollouts used short scripts to inspect geometry, reconstruct prototypes, and search for safer candidates before committing a CIF.

  1. mp-690760, TiH The agent used numpy and periodic-image wrapping to compute Ti-Ti, Ti-H, and H-H distances, found the short Ti-H contacts causing strain, then switched to pymatgen neighbor and symmetry analysis to test a NiAs-like hypothesis before writing a new candidate CIF.
  2. mp-976260, LiTm2Au The agent reconstructed an ideal full-Heusler layout in Python, then swept lattice constants and compared checker outputs across candidates. That turned the checker into a small search loop and let it pick a safer cell size after seeing which values reduced the force proxy most cleanly.
  3. mp-867125, Al2RuPt Instead of hand-editing sixteen atomic sites, the agent wrote a write_cif(a) helper that generated the whole Heusler-style structure programmatically. That made it easy to emit a consistent candidate, validate it, and avoid manual transcription errors.

What changed, exactly?

The architecture change was a shift in responsibility. The old environment owned the loop. The new stack separates what the model should solve from how the model is allowed to solve it.

Before

Classic MultiTurnEnv

The environment stepped the conversation forward, injected feedback, and expected the model to return a final CIF through a chat-facing answer contract. That made iteration fast, but it also tightly coupled task logic, state management, and evaluation behavior.

  • The agent mostly saw score and feedback, not a real tool surface.
  • Answer extraction lived in the chat contract, so format failures could dominate the result.
  • Shared mutable state created a real concurrency bug before the corrected reruns.
  • The benchmark rewarded quick direct repair more than agent workflow quality.
After

RLM + ComposableEnv

The new setup uses a taskset for dataset and metadata, a harness for system prompt and tools, and ComposableEnv as the orchestrator. The model operates through files, checker calls, and sandbox state, with the final answer written to final.cif instead of squeezed through chat formatting.

  • The agent can inspect inputs, run code, write files, and revise against tool results.
  • Task definition and agent policy are cleanly separated.
  • The output contract is file-based, which sharply reduces extraction noise.
  • Failures become more diagnostic: symmetry, formation energy, composition, and workflow quality.

The new mental model

The migration plan boiled the RLM version down to three pieces. That decomposition matters because it gives each layer one job and makes it easier to reason about scaling, tooling, and debugging.

Taskset

Holds the dataset, task metadata, sandbox inputs, and instruction construction. It answers the question: what is the model solving on this rollout?

Harness

Defines the system prompt, available tools, and the working style of the agent. It answers the question: how is the model allowed to work?

ComposableEnv

Owns the rollout loop, state, sandbox orchestration, scoring handoff, and turn budget. It answers the question: how do these pieces run together at scale?

Architecture in one glance

Old:
MultiTurnEnv
  -> prompt the model
  -> inject validator feedback
  -> parse final CIF from chat
  -> score

New:
Taskset + Harness + ComposableEnv
  -> mount task inputs in sandbox
  -> let the agent inspect and edit files
  -> run checker calls during the loop
  -> read final.cif
  -> score the final artifact
The point of the RLM transition was not to make the task easier. It was to make the benchmark honest.

Classic stayed stronger on short direct-feedback evals, especially for smaller models. But RLM exposed something more valuable: whether the model could actually operate under a tool-mediated scientific workflow instead of merely responding well to tightly curated chat feedback.

That distinction matters for training. If a rollout fails because a parser could not extract the answer, you learn almost nothing. If it fails because the model preserved composition but never found a low-energy structure, you learn where the agent policy is weak.

Why the transition matters

A strict 1:1 comparison on short runs does not always favor RLM. Its value is that the harness is easier and cheaper to scale to longer trajectories, larger checker budgets, and broader sweeps, which is where the extra workflow signal starts to pay off.

It separates formatting from competence

In the classic environment, malformed tags or parser-hostile prose could erase otherwise useful structure generation. In RLM, the final artifact lives in a real file, so scoring is tied more tightly to the structure itself.

It turns tools into first-class training context

The model no longer has to simulate a workflow through text alone. It can inspect the unrelaxed CIF, revise files, call a checker, and use the sandbox the way a real agent would.

It makes failure modes legible

The hard problems become visible: composition mismatch, force-proxy failures, spacegroup collapse to P1, and failure to reach low formation energy. Those are the right problems to optimize.

What stayed hard

RLM fixed a lot of interface noise, but it did not solve the underlying scientific challenge. The migration reduced ambiguity. It did not remove difficulty.

Classic exposed quick-answer strength

The corrected multi-turn environment was fast and direct. Models that could infer a prototype and output a strong CIF immediately did well. GPT-5.5 was exceptional there, and the smaller models benefited from the simpler contract.

  • Direct validator feedback in chat encouraged fast local repair.
  • Short runs were useful for solvability checks and cheap baselines.
  • But the task mixed model quality with answer-format fragility.

RLM exposed workflow strength

The RLM harness rewarded models that could use a checker productively, manage files, and spend turns on diagnosis instead of surface repair. GPT-5.5 improved the most under larger budgets, while weaker models often remained stuck in local cleanup.

  • Claude benefited heavily from the file-based output contract.
  • GPT-5.4-mini often preserved chemistry but missed energy and symmetry.
  • Gemini showed upside, but concurrency and early stopping mattered.

Three lessons from the migration

The architecture shift surfaced a few durable principles that apply beyond crystal relaxation.

  1. State isolation is non-negotiable. The classic composition leak showed how quickly concurrent rollouts can invalidate a benchmark when environment state is shared implicitly.
  2. File-based outputs are better than chat-only answer contracts for tool tasks. RLM did not magically improve chemistry, but it dramatically improved validity and extraction reliability.
  3. More turns only help when the agent can spend them well. GPT-5.5 benefited from larger turn and checker budgets; weaker models often used the extra room for conservative, local edits that never crossed the scientific threshold.

The real outcome

The transition from MultiTurnEnv to RLM was a move from a tightly scripted evaluator to a more faithful agent environment. The old loop is still useful as a quick, easy-to-compare baseline. But the RLM harness is the better place to measure what matters next: tool use, revision strategy, and whether the model can turn partial scientific signal into a better structure.

That is why the most important result in the migration report is not just the top-line reward. It is the change in what the reward means. Once format failures and environment leaks stop dominating the outcome, the benchmark starts telling the truth.
